# Автоматизация обработки тикетов поддержки

AI/ML-система для поддержки крупного онлайн-сервиса (200 000 обращений
в сутки, 5 млн активных пользователей): классифицирует входящий тикет,
оценивает риск, маршрутизирует его и — там, где это безопасно — сам отвечает
клиенту по базе знаний. Всё остальное уходит
оператору с готовым черновиком. Каждое автоматическое решение записывается
в аудит-лог и может быть воспроизведено.

Ключевое архитектурное решение: **классификация и маршрутизация синхронны
(бюджет 500 мс) и не зависят от внешних сервисов, а генерация ответа —
асинхронна.** Замер в этом репозитории: один вызов Claude API занял 4 240 мс,
то есть в 8,5 раз больше всего бюджета горячего пути. Поэтому отказ внешнего
LLM-провайдера физически не может нарушить SLA по маршрутизации — он влияет
только на скорость и качество содержательного ответа.

## Зачем это бизнесу

Около 40% обращений — типовые и повторяющиеся, ответ на них уже есть в базе
знаний. Сегодня каждое такое обращение стоит 150 ₽ рабочего времени оператора,
а весь поток — 10,95 млрд ₽ в год. По расчёту в [docs/product.md](docs/product.md)
система автоматизирует 22% потока и высвобождает **≈ 3,58 млрд ₽/год**
операторской ёмкости при прямых затратах 59 млн ₽/год: автоматическая обработка
тикета стоит 0,81 ₽ против 150 ₽ ручной. Эффект реализуется прежде всего как
избежание найма при росте пользовательской базы — обращения растут вместе
с бизнесом, а стоимость поддержки перестаёт. Не менее важен второй эффект:
время до первого ответа падает с целевых 15 минут до секунд, а операторы
перестают печатать один и тот же ответ и занимаются случаями, где действительно
нужен человек.

## Как запустить PoC

Нужен только Python 3.9+. Зависимостей нет, интернет и API-ключи не требуются.

```bash
git clone <этот репозиторий> && cd ml_design
make demo        # или: python3 poc/run_demo.py
make test        # 14 тестов: python3 -m unittest discover -s tests
```

Опционально — с реальной генерацией через Claude API:

```bash
export ANTHROPIC_API_KEY=...
make demo-claude   # или: python3 poc/run_demo.py --provider claude
```

## Какой сценарий демонстрируется

Демо проходит **шесть сценариев** и печатает каждый шаг с таймингами:

| # | Сценарий | Тикет | Что показывает |
|---|---|---|---|
| 1 | Определение темы и риска | T-1001 | Маскирование персональных данных, тема `delivery_status` с уверенностью 0,88, уровень риска low |
| 2 | Поиск по базе знаний и похожим тикетам | T-1001 | Топ-3 статьи с оценками близости, два похожих прошлых тикета |
| 3 | Черновик ответа и маршрут | T-1001 | Решение `auto_answer` по правилу P-6 с объяснением, почему оно принято |
| 4 | Запись решения в аудит | T-1001 | Строка в `logs/decisions.jsonl` с версиями моделей, порогами и таймингами |
| 5 | **Fallback: внешний LLM API недоступен** | T-1013, T-1015 | Circuit breaker размыкается после 3 отказов, автозакрытие отменяется, клиент получает шаблонное подтверждение, тикет уходит оператору, **SLA горячего пути не нарушен** |
| 6 | **Risky path: prompt injection** | T-1010 | Детектор срабатывает, тикет **не доходит до LLM вообще**, эскалация оператору с указанием причины |

Дополнительно демо показывает тикет из запрещённой к автозакрытию категории
(возврат денег), сводку по всем 15 тикетам и замер латентности.

**Результат последнего прогона** (15 тикетов): 6 автоответов (40%),
5 черновиков оператору (33%), 3 эскалации (20%), 1 в общий разбор (7%).
Латентность горячего пути на 200 прогонах: p50 ≈ 0,13 мс, p95 в пределах
0,2–0,4 мс. Абсолютные значения зависят от машины и её загрузки; устойчив
здесь только порядок величины — доли миллисекунды при бюджете 500 мс.

> Оговорка: 15 тикетов — демонстрация работоспособности, а не оценка качества.
> Доля автоответов на реальном трафике измеряется только в shadow-режиме,
> см. [docs/ml.md](docs/ml.md).

## Что реально реализовано, а что архитектурный дизайн

| Компонент | В PoC | В целевой системе |
|---|---|---|
| Маскирование персональных данных | **Реализовано** — регулярные выражения (телефон, почта, карта) | То же + проверка полноты на размеченной выборке |
| Классификация темы | **Реализовано** — правила + kNN на TF-IDF по 40 примерам | Логистическая регрессия поверх эмбеддингов multilingual-e5-small, ~20 000 размеченных тикетов |
| Детекторы риска, prompt injection | **Реализовано** — правила и паттерны | То же + вторым слоем модель-классификатор атак |
| Поиск по базе знаний | **Реализовано** — TF-IDF по 10 статьям | ANN-поиск по векторной базе (Qdrant / pgvector) |
| Policy engine (7 правил, пороги) | **Реализовано** полностью | То же + управление порогами через реестр моделей |
| Аудит-лог решений | **Реализовано** — JSON Lines + проверка схемы | Kafka → ClickHouse + S3 с Object Lock, 3 года |
| Circuit breaker и деградация | **Реализовано** — 3 отказа → размыкание на 30 с | То же + переключение на резервного провайдера |
| Генерация черновика | **Реализовано в двух вариантах**: детерминированная заглушка (офлайн) и реальный Claude API через urllib | Официальный SDK, кэш ответов, проверка на выходе |
| Замер латентности | **Реализовано** — p50/p95/p99 на 200 прогонах | Метрики в реальном времени, алерты |
| Очередь, воркеры, масштабирование | Только дизайн | Kafka + горизонтальные воркеры |
| Интерфейс оператора | Только дизайн | Встраивание черновика в существующее рабочее место |
| Обучение и переобучение моделей | Только дизайн | MLflow, реестр моделей, переобучение по расписанию |
| Хранилища (PostgreSQL, векторная база, Redis) | Только дизайн — данные лежат в JSONL-файлах | См. [docs/architecture.md](docs/architecture.md) |

Ключевые упрощения помечены в коде комментарием `УПРОЩЕНИЕ:` с указанием,
чем каждое из них заменяется в целевой системе (`classifier.py`, `retrieval.py`,
`textutil.py`, `llm.py`, `audit.py`, `pipeline.py`).

## Допущения и ограничения

- **Бизнес-вводные взяты из задания** (200 000 тикетов/день, 150 ₽ за тикет,
  SLA 15 минут, CSAT 4,2, reopen rate 9%, ≈40% типовых). Всё остальное —
  собственные допущения, явно выписанные в
  [docs/product.md](docs/product.md), раздел 5: доля проходящих пороги,
  охват suggest, длина промпта, цена LLM, стоимость инфраструктуры.
  Расчёты воспроизводимы подстановкой.
- **Домен конкретизирован до маркетплейса**: в задании «крупный онлайн-сервис»,
  а PoC нужны были правдоподобные категории. Архитектура и экономика от выбора
  домена не зависят.
- **Датасет синтетический**: 15 тикетов, 10 статей базы знаний, 40 размеченных
  примеров написаны вручную под демонстрацию сценариев. Метрики качества
  (macro-F1, Recall@3) на нём **не измерялись и не приводятся** — это было бы
  подгонкой под собственные данные.
- **Латентность PoC (доли миллисекунды) не переносится на целевую систему**: в PoC нет
  эмбеддинг-модели и сетевых вызовов, которые и составляют основной бюджет.
  Постатейный бюджет на 225 мс — в [docs/architecture.md](docs/architecture.md),
  раздел 4.
- **Порог 0,55 для автоответа подобран на 15 тикетах** и в реальной системе
  калибруется на отложенной выборке под целевой precision.
- Не реализованы: очередь, интерфейс оператора, обучение моделей, хранилища,
  аутентификация, многоканальность.

## Глоссарий

| Термин | Расшифровка и значение здесь |
|---|---|
| **AHT** | Average Handling Time — среднее время обработки одного тикета оператором |
| **ANN** | Approximate Nearest Neighbours — приближённый поиск ближайших соседей в векторной базе |
| **ARR** | Automated Resolution Rate — доля тикетов, решённых без оператора и не переоткрытых за 7 дней |
| **Circuit breaker** | Предохранитель: после N отказов подряд вызовы внешнего сервиса отсекаются, чтобы не копить таймауты |
| **Cohen's kappa (κ)** | Мера согласованности двух разметчиков с поправкой на случайные совпадения |
| **CSAT** | Customer Satisfaction Score — оценка удовлетворённости клиента, шкала 1–5 |
| **FCR** | First Contact Resolution — доля вопросов, решённых с первого обращения |
| **FTE** | Full-Time Equivalent — эквивалент полной занятости одного сотрудника |
| **Guardrail-метрика** | Метрика, которую не улучшают, а следят, чтобы она не ухудшилась (reopen rate, CSAT) |
| **Human-in-the-loop** | Человек в контуре принятия решения: правит черновик, разбирает эскалации |
| **JSON Lines (JSONL)** | Формат файла: один самостоятельный JSON-объект на строку; удобно дописывать и читать построчно |
| **kNN** | k Nearest Neighbours — классификация по k ближайшим размеченным примерам |
| **LLM** | Large Language Model — большая языковая модель (здесь Claude) |
| **LLM-as-judge** | Использование LLM в роли оценщика качества ответов на выборке |
| **macro-F1** | Среднее F1 по всем категориям, каждая весит одинаково независимо от объёма |
| **MRR** | Mean Reciprocal Rank — средний обратный ранг верного документа в выдаче |
| **ONNX** | Open Neural Network Exchange — открытый формат моделей; здесь: способ запускать эмбеддинг-модель на CPU быстро и без тяжёлых фреймворков |
| **p95** | 95-й процентиль: значение, ниже которого укладываются 95% измерений |
| **PII** | Personally Identifiable Information — персональные данные (телефон, почта, карта) |
| **Prompt injection** | Атака: попытка через текст обращения переписать инструкции модели |
| **RAG** | Retrieval-Augmented Generation — генерация ответа с опорой на найденный документ |
| **Reopen rate** | Доля закрытых тикетов, переоткрытых клиентом (здесь — за 7 дней) |
| **Shadow-режим** | Система считает решения на живом трафике, но не исполняет их |
| **SLA / SLO** | Service Level Agreement — обещание уровня сервиса; SLO — внутренняя цель (здесь 500 мс) |
| **Suggest-режим** | Черновик готовится автоматически, отправляет его человек |
| **TF-IDF** | Term Frequency – Inverse Document Frequency: вес слова = частота в документе × редкость в коллекции |
| **TTFR** | Time To First Response — время до первого ответа клиенту |
